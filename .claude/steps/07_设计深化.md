# Step 07：设计深化

## 输入
Step 06 确认的5个概念

## 执行

### 深化顺序规则（先放大主特征，再补工程细节）

每个概念的7步设计思考链必须按以下顺序执行，不允许跳步：

**先放大（第1-3步优先）：**
1. 主轮廓更明确——从Step 06的hero_feature出发，把主视觉特征的几何关系定义清楚
2. 主视觉锚点更狠——放大hero_feature的视觉冲击，不要缩水
3. 功能卖点更可见——让hard_sell_point在产品外形上直接可见

**再补齐（第4-7步）：**
4. 分件逻辑
5. 传感器/应急包/驱动占位
6. CMF方向（严格在品牌DNA范围内）
7. 成本/认证约束

**严禁在补齐阶段削弱第1-3步的视觉张力。** 如果非成本类工程约束和主特征冲突，优先保留主特征，工程上找替代方案。成本类约束（BOM超走廊）不适用此规则——已通过Step 05硬杀的概念不应在此步骤重新引入成本风险。

对每个概念做完整的设计定义，覆盖7步设计思考链。
这是整个系统最重的步骤，每个概念的产出量最大。

### 7步设计思考链（每个概念都必须完成全部7步）

**每步最低内容要求**：
7步思考链每一步不能只写一句话摘要。最低要求：
- 第1步硬性约束：≥3条具体约束+冲突说明
- 第2步体块关系：≥3个功能体块+排列方式+连接关系
- 第3步轮廓比例：具体比例数字+关键截面描述
- 第4步分件策略：分几件+每件工艺+装配方向
- 第5步关键细节：接口/线缆/散热/密封/维护各一条
- 第6步CMF：色彩方向+材料+表面处理各一条
- 第7步设计语言：3关键词+第一注意力点+vs竞品区别

不满足最低要求的深化 → 补完后再进入下一概念。

**第1步：硬性约束框架**
- 产品的不可动约束有哪些？（光源面积、驱动器体积、散热表面积、安装方式限制、认证要求...）
- 这些约束决定的最小包络体积是多少？
- 哪些约束之间有冲突？（例如：散热面积要大 vs 产品要轻薄）

**【R18注意】功能约束 vs 位置约束**：Step 02原则是"锁功能关系，不锁具体位置"。但Step 07第5步要求具体散热路径/密封路径/维护开口位置——这些是**实现层的位置决策**，不是Step 02意义上的设计自由度限制。区别：
- Step 02锁的是"散热面积必须足够"（功能约束） 
- Step 07第5步决定的是"散热路径从顶面走还是侧面走"（实现选择，在功能约束框架内做最优选择）
工程约束与视觉张力冲突时，优先保留主特征，工程上找替代方案（见深化顺序规则）。

**第2步：主体块关系**
- 产品由哪几个功能体块组成？（例如：光学模块、散热模块、驱动模块、安装结构）
- 这些体块怎么排列？（并排/叠放/包裹/悬挂/嵌套）
- 体块之间的连接关系是什么？
- 体块关系决定了产品的基本形态走向——明确写出来

**第3步：整体轮廓和比例**
- 产品的整体外轮廓（用几何语言描述，不用比喻）
- 高宽厚比例（具体数字或比例关系）
- 主视觉特征在产品上的位置和面积占比
- 关键截面形状（至少描述1个关键截面）

**第4步：分件策略**
- 外壳分几件？怎么分？
- 分件线在哪里？分件线是设计特征还是尽量隐藏？
- 每件的主要工艺（铝挤/注塑/钣金/压铸 + 表面处理）
- 装配方向和装配顺序

**第5步：关键细节**
- 接口位置和类型
- 线缆从哪里进、走哪条路径、藏在哪里
- 散热路径（热源在哪、热量怎么传导到外壳）
- 密封路径（如需IP防护）
- 维护开口在哪、怎么打开
- 安装/固定方式的具体结构

**第6步：CMF方向**
- Color：主色调方向（不需要精确到Pantone，给方向）
- Material：主体材料+感觉（金属冷感/塑料温润/混搭对比...）
- Finish：表面处理（哑光/亮面/磨砂/阳极氧化/喷涂...）

**第7步：设计语言总结**
- 这个产品想给人什么感受？（用3个关键词）
- 这个产品在货架上/使用场景中最先被注意到的是什么？
- 这个产品和竞品放在一起，视觉上的核心区别是什么？
- 这个产品在**Step 02**品类设计谱系图上的位置在哪？与客户当前坐标的距离是否在设计半径内？

### 第8步：概念完整性校验（concept_integrity_check）

深化完成后，必须对照 Step 05 原始钩子卡进行完整性校验：

```yaml
integrity_check:
  concept_id: "C-01"
  
  # 校验1：Hero Feature 是否被稀释？
  original_hero: "正中央贯穿全高的深V散热峡谷"  # 从Step 05钩子卡复制
  deepened_hero: "正面中央纵向散热槽，深度12mm，宽度8mm"  # Step 08第3步的描述
  hero_preserved: true/false
  # 如果false：说明哪里被削弱了，给出修复方案
  
  # 校验2：visual_test 是否仍然通过？
  original_visual_test: "不懂产品的人能说出'散热很强'"
  post_deepening_pass: true/false
  # 如果false：哪个工程约束导致了削弱？能否找替代方案？
  
  # 校验3：痛点回应是否仍然可见？
  original_solves_what: "散热不足导致光衰快"
  still_visible_in_form: true/false
  # 如果false：深化过程中哪一步丢失了？

  # 校验4：购买句是否仍然成立？
  original_purchase_sentence: "我们这款产品比普通产品更____，因为你一眼能看到____"
  post_deepening_valid: true/false
  # 如果false：深化后的hero feature是否仍能支撑这句话？需要修改购买句还是修改设计？
```

**校验不通过的处理**：
- 回退到第1-3步，在不削弱 Hero Feature 的前提下重新处理工程约束
- 记录冲突：具体是哪个工程约束和视觉张力冲突
- 如果无法兼容：标注[DESIGN_CONFLICT]，在用户确认时提出，由人决定取舍

### 第9步：渲染锚定准备

为 Step 08 渲染控制准备材料（本步骤内部环节，非独立步骤）：

- **确认 render_anchor**：从 Step 06 概念卡中的 render_anchor.primary_reference_image 确认参考图是否仍然适用
  - 如果经过7步深化后造型方向发生变化，需要更换参考图（从素材库重新检索）
  - 如果没有变化，保留原参考图
- **写出 delta_from_reference**：基于7步深化的结果，更新"和参考图相比的具体差异"
  - 差异描述要用第2-3步的几何语言，不用感觉词
- **列出3条核心禁止项**：从第4-5步中提取最容易被渲染AI误解的元素

```yaml
render_prep:
  reference_image: "素材库ID或产品图URL"
  delta_description: "和参考图相比的2-3条关键修改"
  top_3_prohibitions:
    - "禁止项1"
    - "禁止项2"
    - "禁止项3"
```

### 输出格式
按 templates/设计深化模板.yaml 格式输出。
5个概念分别输出，每个概念一份完整的8步定义（7步设计思考链 + 渲染锚定准备）。

### 客户偏好加载
深化前加载客户记忆 `.claude/clients/{客户名}/preferences.yaml`（如有），根据客户偏好调整CMF方向和渲染风格倾向。

### 【R15强制】F20+F25审计闸门（Step 07独立审计要求）

Step 07 是整个流程中唯一原来缺失审计闸门的步骤。本版本起，Step 07结尾必须执行F20+F25审计。

**F20审计范围（Step 07特有）**：
对每个概念深化中的关键判断，审计以下内容：
- 第1步硬性约束：约束来源是否为FACT级？INFERENCE来源的约束是否被当成HARD约束使用？
- 第3步比例数字：高宽厚比例是否有参照依据（素材库图片/Step 02标准比例），还是凭空生成？
- 第6步CMF：材料选择是否在Step 01 BOM走廊内？凭空引入高成本材料→标HYPOTHESIS
- 第7步设计语言关键词：3个关键词是否有Step 06视觉审查中的描述对应？

```yaml
step07_f20_audit:
  concept_id: ""
  constraint_sources_verified: true/false    # 第1步约束均为FACT级来源
  geometry_numbers_sourced: true/false       # 第3步比例有参照依据
  cmf_within_bom: true/false                 # 第6步材料在成本走廊内
  language_keywords_backed: true/false       # 第7步关键词有视觉证据
  inference_used_as_hard: false              # INFERENCE被当成HARD约束=FAIL
  overall_status: ""    # FACT/INFERENCE/HYPOTHESIS占比
```

**F25审计范围（Step 07特有）**：
深化后的购买句是否仍然成立？分配角色是否仍匹配？

```yaml
step07_f25_audit:
  concept_id: ""
  purchase_sentence_still_valid: true/false
  market_role_still_fits: true/false
  new_risks_introduced: []    # 深化过程引入的新风险
  new_risks_disposition: []   # 每条新风险的处置决定（必填，不允许留空）
```

**【R07强制】新风险处置流程**：`new_risks_introduced` 非空时，每条风险必须在进入 Step 08 前完成处置：
- **可降低风险**（如换材料/调结构）→ 记录降低方案，更新概念描述，标注 `disposition: MITIGATED`
- **需用户决策**（超出AI判断范围）→ 明确列出"需用户确认：___"，等待用户回复，标注 `disposition: USER_DECISION_NEEDED`
- **接受风险**（已知风险，有商业理由）→ 记录接受理由，标注 `disposition: ACCEPTED_WITH_REASON`
- **不可接受风险**（阻断性风险）→ 标注 `disposition: BLOCKER`，该概念退出深化，回到 Step 05 补选

禁止 `new_risks_introduced` 有内容但 `new_risks_disposition` 留空——留空=系统执行了无后果的风险记录，等同于没执行。

两项审计全部通过后，才能进入 Step 08。

### 分批执行规则
因为5个概念×8步内容量很大，分批执行：
- 先做概念1和概念2的完整8步 → 输出 → 等用户确认（确认检查点，非决策断点）
- 再做概念3和概念4 → 输出 → 等用户确认（确认检查点，非决策断点）
- 最后做概念5 → 输出 → 等用户确认（确认检查点，非决策断点）
