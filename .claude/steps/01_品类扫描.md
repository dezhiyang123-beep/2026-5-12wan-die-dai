## 本步骤必须调用的框架

| 框架 | 层级 | 触发条件 | 必须产出 |
|------|------|---------|----------|
| F02 认证门槛 | 系统级必跑 | 每个项目 | 认证清单（通过/需投入/阻断） |
| F10 成本走廊 | 系统级必跑 | 每个项目 | 零售→FOB→BOM上限→关键件预算 |
| F04 品类吸引力 | 条件触发 | 未指定子品类/多品类探索/新品类 | 细分品类排序表 |

条件触发框架：触发条件满足时必须跑，跳过=调研质量降低。不满足时跳过并记录原因。

**Step 01结尾必须调用F20**，对以下关键判断逐条审计：
- 市场规模判断
- 价格带定位
- 认证可行性判断
- 子品类选择（如有F04）
- 价值链利润判断（如有F05）
- 行业结构判断（如有F21）
- 法规约束判断（如有F11）
- 反面证据的应对判断

输出时必须把市场事实（FACT）、AI推断（INFERENCE）、用户判断（USER_SIGNAL）分开标注。

## 本步骤目标
一口气完成品类认知建设：锁定品类+认证门槛+市场数据，为后续设计决策提供事实基础。

## 框架调用
1. F02 合规/认证门槛粗筛（系统级必跑）
2. F10 目标成本走廊（系统级必跑）— 产出初始版成本走廊，Step 03可更新，以最后一次为准
3. F04 品类吸引力矩阵（Conditional：未指定子品类时触发）

## 数据闸门（三批执行，保留原有逻辑）

### 第一批：证据采集
按固定搜索源梯队搜索以下数据，每条记入证据表（templates/证据表模板.yaml）：

**必采数据**：
- 市场规模（SEC EDGAR → 行业协会 → 报告机构公开页）
- 价格带分布（品牌官网PDP → 零售商 → 评测页）
- 认证要求（DLC/UL/FCC官网 → ENERGY STAR → 品牌宣传页）
- 主要竞品清单（至少5个品牌，含价格定位）

**【R6强制】客户在目标品类中的现有产品扫描**（防止Alta事件重演）：
交叉扫描以下三个来源，确认客户是否已有目标品类产品：
1. `.claude/clients/{客户名}/project_history.yaml` — 检查历史项目中有无同品类记录
2. `.claude/knowledge/素材索引/**/{客户名}*.yaml` — 检查素材库中有无客户该品类产品
3. 客户官网产品线 — 搜索"{客户名} {品类关键词} site:{客户官网}"

**如发现客户已有目标品类产品**：
- 必须列出所有已知产品型号、价格、上市时间
- Step 02 F18谱系图必须以这些产品为基线（而非"首款"假设）
- Step 03 5码提取必须基于这些现有产品

**如未发现**：记录"已扫描三来源，未发现{客户名}在{品类}的现有产品，首款假设成立"，标注为 status: FACT（B级，基于扫描结果）。

**竞品分析最低颗粒度要求**：
每个竞品品牌必须包含：
- 代表产品型号（≥1个具体型号名）
- 零售价格区间
- 设计水平初评（1-5分+一句话理由）
- 设计特征描述（轮廓/散热/CMF/安装，每项一句话）
不允许只写"品牌名+一句话定位"的粗略清单。

**选采数据**（信息可得时采集，不阻断）：
- 增长趋势（CAGR）
- 渠道结构（B2B/B2C/线上线下占比）
- 中国OEM概况（公司官网 → GSXT → ImportYeti）

每条数据必须含：Claim_ID、数值、来源URL、页面可见摘录。
**第一批完成后输出证据表，等用户确认（确认检查点，非决策断点）。**

### 反面证据采集

**在第一批证据采集同期完成。这是思维纪律，不是数据精度要求。**

必须找出至少3条"为什么这个品类/方向可能失败"的结构性理由。

```yaml
counter_evidence:
  - id: "CE-01"
    argument: ""           # 结构性论点（不接受"竞争激烈"这种空话）
    evidence_type: ""      # [数据] / [案例] / [AI推理]
    source: ""             # URL，或标注 [AI推理] 并说明推理链
    impact_if_true: ""     # 如果这条成立，对本项目意味着什么？
    mitigation: ""         # 有没有应对方案？没有也要写"暂无"
  - id: "CE-02"
    ...
  - id: "CE-03"
    ...
```

**要求**：
- 每条必须是结构性论点（如：品类天花板低、技术路线将被替代、渠道在收缩、核心零件供应集中度过高）
- 来源可以是行业报告、竞品失败案例、市场饱和数据
- 如果找不到硬数据，可标注 `[AI推理]` 并写出推理链，但不能全部都是AI推理（至少1条有外部来源）
- **反面证据不阻断流程**，但会在 Step 03 方向决策时作为风险提示呈现给用户

### 第二批：数据验证
逐条验证：
- 页面摘录是否真的包含该数字？
- 高影响字段（市场规模、价格带、认证版本号）：第二独立来源 + 反面检验
- 标注：VERIFIED / DERIVED / UNKNOWN / FAIL

**证据等级标注**（新增）：
```
A级：客户原话 / 官方数据库 / 上市公司披露        → 可直接作为硬约束
B级：多平台评论反复出现 / 行业报告公开数据        → 可作为设计依据
C级：AI从相邻数据推断 / 单一来源未交叉验证        → 可作为参考，不能做淘汰依据，必须标注风险
D级：纯创意假设 / 无任何证据支撑                  → 不能作为约束，仅供灵感
```

**【R21强制】FACT级标注必须有原始来源验证**：
- status=FACT 的判断必须附：原始来源URL 或 文档名称+页码 + 关键摘录（≤50字）
- 禁止只写"来源：行业经验"或"来源：AI推断"就标FACT
- FACT标错比INFERENCE飘移更危险（R21教训：R600a法规"强制"事实错误、Yeti V品类误判等）
- 已知易错事实见 `.claude/knowledge/已知事实修正库.yaml`，标FACT前必须对照检查
- **枚举值schema**（R2防止发明新值）：
  - verification_status 仅限：VERIFIED / DERIVED / UNKNOWN / FAIL（四选一，无其他值）
  - evidence_level 仅限：A / B / C / D
  - status 仅限：FACT / INFERENCE / HYPOTHESIS / USER_SIGNAL / NEEDS_VALIDATION
  - counter_evidence verdict 仅限：ADDRESSED / UNADDRESSED / PARTIAL_MITIGATION
  - 发明规则外枚举值 → 自检必须标FAIL

**第二批完成后输出验证表，等用户确认（确认检查点，非决策断点）。**

### 第三批：品类扫描结论

基于验证通过的数据输出：

```yaml
# 品类锁定
category: ""
sub_category: ""
target_market: ""
mode: "M1/M1a/M2/M3"

# 认证门槛（F02输出）
certifications:
  required: []        # 必须有的认证
  nice_to_have: []    # 加分认证
  blockers: []        # 阻断项（如有）

# 市场概况
market_size: ""       # [VERIFIED/DERIVED] + 数值 + 来源URL + evidence_source
market_size_evidence_source: ""  # "SEC EDGAR" / "行业报告URL" / "AI推断（推理链：___）"
price_tiers:
  low: { range: "", brands: [], evidence_source: "" }
  mid: { range: "", brands: [], evidence_source: "" }
  high: { range: "", brands: [], evidence_source: "" }

# 成本走廊（F10输出，提前锁定）
cost_corridor:
  target_retail: ""
  target_retail_evidence_source: ""   # "品牌官网PDP" / "零售商列表URL" / "AI推断（推理链：___）"
  target_fob: ""
  target_fob_evidence_source: ""      # "客户提供" / "行业规律推算：___" / "AI推断（推理链：___）"
  bom_ceiling: ""
  bom_ceiling_evidence_source: ""     # "F10计算公式：零售价×_÷_÷_" / "AI推断"
  key_cost_drivers: []

# 竞品清单（给Step 03用）
competitors: []       # 至少5个品牌名

# 待验证清单
unknowns: []          # UNKNOWN项集中列出
evidence_level_warnings: []  # C级数据的风险提示
```

## 输出
品类扫描报告（含上述YAML结构）。
输出后等用户确认，确认后进入 Step 02（品类设计全景学习）。
