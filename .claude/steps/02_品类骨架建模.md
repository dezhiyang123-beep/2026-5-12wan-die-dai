# Step 02：品类骨架建模

## 目标
建立目标品类的"器官图"——在开始找灵感之前，先搞清楚这个品类的产品**必须有什么、不能乱动什么、哪里可以创新**。

**没有品类骨架，禁止进入 Step 04。**

## 输入
- Step 01 品类扫描报告（品类、竞品清单、价格带）
- 素材库中该品类的图片（如有）
- 系统自身对该品类的知识

## 【R3强制】上游约束Status复核

执行第一步前，必须先复核Step 01传入的约束：

```yaml
upstream_status_review:
  step: "Step 02 执行前"
  review_items:
    - constraint: ""          # 来自Step 01的约束描述（如"R600a强制使用"）
      original_status: ""     # Step 01标注的status（FACT/INFERENCE/HYPOTHESIS）
      evidence_level: ""      # A/B/C/D
      can_be_used_as: ""      # 基于status决定的使用权限
      action: ""              # ACCEPT_AS_HARD / ACCEPT_AS_SOFT / NEEDS_VALIDATION / REJECT
```

**Status权限规则**（不可绕过）：
- FACT（A/B级）→ 可作为 HARD 约束，直接限制设计
- INFERENCE（推理链完整）→ 只能作为 SOFT 约束，标注"推断来源：___"
- HYPOTHESIS / USER_SIGNAL → 只能作为探索方向，不能限制创新区域
- NEEDS_VALIDATION → 本步骤不能使用此约束，列入待验证清单

未经此复核的INFERENCE/HYPOTHESIS约束传递到下游 = 系统性错误。

## 本步骤必须调用的框架

| 框架 | 层级 | 触发条件 | 必须产出 |
|------|------|---------|----------|
| F18 品类设计语言 | 系统级必跑 | 每个项目 | **品类设计谱系图**（≥8品牌，7维度评分，族群聚类，设计空白）**【品类适配】维度3/4/5/7按品类替换见框架库F18-品类适配表** |
| F03 渠道×价格带 | 条件触发 | 主动ODM/价格不清/渠道影响购买 | 渠道×价格带矩阵 |
| F22 竞争定位图 | 条件触发 | 竞品≥5且坐标轴有证据支撑 | 竞争定位图（含轴定义+品牌坐标+空白区域） |
| F24 雷达图 | 条件触发 | 需多维可视化且数据≥3对象 | 竞品雷达图（可视化输出，非判断依据） |
| **F20 证据到结论审计** | **系统级必跑** | **每个项目** | **Step 02所有关键判断的审计表** |

**F18品类设计谱系图是本步骤最重要的产出。没有谱系图，禁止进入Step 03。**

谱系图必须包含：
- ≥8个品牌的设计语言分析（每品牌：代表产品+7维度评分+每维度依据+置信度）
- **设计水平评分必须使用F18的7维度评分标准，禁止无标准打分**
- 品牌聚类成3-6个设计语言族群
- 设计语言空白识别（没有品牌占据的组合）
- **所有空白必须交给F20审计，不得直接将空白等同于机会**
- **空白validated判定标准（R11）**：validated = 空白+用户需求有B级以上证据+技术可行+无已失败案例；conditional = 空白存在但需求证据仅C级；false_blank = 有人做过但失败了。三类判定必须附证据等级。
- 设计奖覆盖情况（品类内有无iF/Red Dot获奖产品）

**Step 02结尾必须调用F20**，对以下关键判断逐条审计：
- 品类骨架三层分类的每个判断（尤其是身份锚点 vs 强约束 vs 可创新区域的分界）
- F18谱系图中的设计空白是否为真实机会
- F22定位图中的空白区域是否可进入
- 品类假设清单中每个假设的type分类是否合理

## 执行

### 第一步：品类器官识别

列出该品类产品的所有"器官"（功能组成部件）。

以电钻为例：
```yaml
category_organs:
  - name: "夹头/chuck"
    function: "夹持钻头/批头"
  - name: "齿轮箱/gearbox"
    function: "变速+扭矩放大"
  - name: "电机仓/motor housing"
    function: "容纳电机+承受扭矩反力"
  - name: "握把/grip"
    function: "用户握持+施力+控制方向"
  - name: "扳机/trigger"
    function: "启动/调速"
  - name: "电池包/battery pack"
    function: "供电+配重"
  - name: "散热口/vents"
    function: "电机散热"
  - name: "模式切换环/clutch ring"
    function: "切换钻/拧/冲击模式"
  - name: "挂钩/belt hook"
    function: "挂在腰带上"
```

### 第二步：三层分类

将品类的所有造型要素分为三层：

```yaml
category_skeleton:
  # 第1层：品类身份锚点（动了就不像这个品类）
  identity_anchors:
    - element: "前端有夹持/钻孔器官"
      why: "用户看到前端夹头才认出这是电钻"
      confidence: high
    - element: "有明确的握持+扳机启动结构"
      why: "所有用户都期望食指扣扳机控制"
      confidence: high
    - element: "单手可控制方向"
      why: "电钻的核心使用方式"
      confidence: high

  # 第2层：强约束（可微调，但不能随便改）
  hard_constraints:
    - element: "握把角度与电机轴的关系"
      why: "影响施力方向和手腕疲劳"
      flexibility: "可在±10°范围内调整"
      confidence: high
    - element: "重心在握把附近或略前"
      why: "重心太后会导致钻头抖动"
      flexibility: "可通过电池位置微调"
      confidence: medium
    - element: "散热面积需满足电机散热需求"
      why: "散热不足=电机过热=寿命短"
      flexibility: "开孔位置/形式可变，面积不能少"
      confidence: high

  # 第3层：可创新区域（设计自由度最大的地方）
  innovation_zones:
    - element: "外壳整体轮廓"
      opportunity: "在不改变器官位置的前提下重新定义外形"
    - element: "分件线走向"
      opportunity: "可以变成设计特征而非隐藏"
    - element: "CMF（颜色/材质/表面处理）"
      opportunity: "品牌语法范围内自由发挥"
    - element: "护角/防摔表达"
      opportunity: "橡胶包胶的范围和形态"
    - element: "散热口形态"
      opportunity: "在满足面积需求的前提下改变开孔图案"
    - element: "指示灯/状态显示"
      opportunity: "位置、形式、亮度都可以创新"
    - element: "挂钩/附件系统"
      opportunity: "可以重新设计"
```

### 第三步：置信度标注

每个要素标注置信度：

| 置信度 | 含义 | 使用权限 |
|--------|------|----------|
| high | 多款同品类产品一致，且有明确工程/人机原因 | 可作为硬约束 |
| medium | 大部分产品一致，但有少数例外 | 需用户确认后使用 |
| low | AI推断，无充分证据 | 只能作为假设，不得限制创新 |

**关键原则：锁功能关系，不锁具体位置。**

错误写法："电池包必须在底部" ← 锁死了位置
正确写法："电池必须保证重心平衡、插拔顺畅、握持不干涉" ← 锁功能关系，位置可以创新

### 第四步：典型比例关系

记录该品类的典型比例（给后续概念生成做参照）：

```yaml
typical_proportions:
  description: "电钻的典型体量分配"
  head_volume: "约40%（电机+齿轮箱+夹头）"
  grip_volume: "约30%（握把+扳机）"
  battery_volume: "约30%（电池包）"
  overall_ratio: "长:高:宽 ≈ 1:0.7:0.4"
  visual_weight_center: "偏前偏上（暗示前冲力量）"
  note: "这是行业平均值，不是硬约束。突破比例是创新方向之一。"
```

### 第五步：常见失败造型

列出该品类中常见的造型失败模式（给后续评审用）：

```yaml
common_failures:
  - failure: "机头太大，头重脚轻"
    why_bad: "看起来会往前倾倒，没有安全感"
  - failure: "握把太细"
    why_bad: "看起来握不住，缺乏信任感"
  - failure: "电池包和机身断裂感"
    why_bad: "看起来像两个产品拼在一起"
  - failure: "过度装饰，线条太多"
    why_bad: "看起来像玩具不像专业工具"
```

### 第六步：品类假设清单（为 Step 05 品类假设挑战准备）

列出该品类"所有人默认为真"的5-8个假设，并分类：

```yaml
category_assumptions:
  - assumption: "夹头在最前端"
    type: identity_anchor     # 禁止挑战
    
  - assumption: "握把在电机正下方"
    type: hard_constraint     # 谨慎挑战，需证明收益
    
  - assumption: "电池包在底部"
    type: convention          # 可以挑战
    
  - assumption: "散热口在两侧"
    type: convention          # 可以挑战
    
  - assumption: "机身是直线型"
    type: convention          # 可以挑战
    
  - assumption: "状态指示灯很小很不起眼"
    type: surface_habit       # 鼓励挑战
    
  - assumption: "挂钩是外露金属件"
    type: surface_habit       # 鼓励挑战
```

## 输出

完整的品类骨架文档，包含：器官图 + 三层分类 + 置信度 + 典型比例 + 常见失败 + 假设清单 + 品类设计谱系图（调用F18生成，含品牌坐标和设计语言空白）。

输出后等用户确认（确认检查点，选择题模式，非决策断点）：

```
品类骨架已生成。请确认以下关键判断：

1. "前端夹持器官"是品类身份锚点，不能动。
   A. 正确  B. 可以有例外  C. 不对

2. "握把角度"是强约束，可微调±10°。
   A. 正确  B. 范围应该更大  C. 其实可以大改

3. "���池包在底部"是行业惯例，可以挑战。
   A. 正确  B. 不对，这是强约束  C. 不确定
   
...
```

用户确认后，品类骨架锁定，进入 Step 03。
