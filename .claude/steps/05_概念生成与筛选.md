# Step 05：概念生成与筛选（原 Step 06+07 合并）

## 输入
- Step 03 选定方向 + 需求→造型意图翻译表（含校验结果）
- Step 03 品牌红线表/绿灯表
- Step 02 品类设计谱系图（Step 02调用F18产出）
- Step 04 造型参照卡（含素材库图片链接）
- Step 04 使用场景约束清单（form_factor_constraints）
- 客户记忆（如有）

## 框架调用

| 框架 | 层级 | 触发条件 | 必须产出 |
|------|------|---------|----------|
| F14 概念覆盖矩阵 | 步骤级必备 | Step 05执行时必跑 | 覆盖检查表（视觉特征/BOM档/策略来源） |
| F15 Pugh概念筛选 | 步骤级必备 | Step 05执行时必跑 | Pugh评分矩阵+硬杀记录 |
| **F20 证据到结论审计** | **系统级必跑** | **每个项目** | **最终5方案的推理审计** |
| **F25 购买理由审计** | **系统级必跑** | **每个项目** | **最终5方案各自的6角色购买理由审计** |
| F24 雷达图 | 条件触发 | ≥3概念需多维可视化对比 | 概念间雷达图（可视化输出，非判断依据） |

## 核心理念

每个概念必须能回答：**"这个造型为什么长这样？因为它要让用户一眼看懂{某个痛点}被解决了。"**

追溯不到痛点的概念不允许存在。

## 执行

### 阶段A：造型策略展开

从 Step 03 需求→造型意图翻译表中，提取已确认的造型策略（通常3-5条）。

对每条策略定义具体的造型逻辑：
- `geometry_rules`：具体的几何约束（不用感觉词）
- `visual_test`：傻瓜式验证标准
- `matched_references`：链接 Step 04 的造型参照卡

**输出后等用户确认策略展开。**

### 阶段B：概念生成（后台，16个初始概念）

**6种生成方法**（合计16个概念）：

| 方法 | 数量 | 逻辑 | 灵感来源 |
|------|------|------|----------|
| 单策略深挖 | 4个 | 一条策略，不同参照展开 | Step 04 同品类+跨品类参照 |
| 策略交叉 | 4个 | 两条策略组合 | Step 04 同品类+跨品类参照 |
| 反向激进 | 2个 | 故意违反某条策略常规 | Step 04 参照 |
| 细节拼接 | 2个 | 从不同产品各取最多2个细节组合 | Step 04 细节级灵感卡 |
| Wildcard | 2个 | 视觉发现驱动，不走结构化策略 | Step 04 路径B |
| **品类假设挑战** | **2个** | **挑战品类的1个行业惯例** | **Step 02 品类假设清单** |

**细节拼接规则**：
- 每个概念**最多2个外来细节**，不能更多（防四不像）
- 所有细节必须服务同一个**设计动词**（如shield/compress/float/wrap）
- 组合后必须回应消费者痛点 + 通过品牌语法检查

**Wildcard Creator 规则**：
- 灵感来源是 Step 04 路径B 的视觉发现
- 不需要严格遵循阶段A的造型策略
- 但必须满足：回应消费者痛点 + 通过品牌语法
- 目的：模拟设计师"翻图时灵光一闪"的过程

**品类假设挑战规则**（V4.3新增）：
- 从 Step 02 品类假设清单中选 2 个标记为 `convention` 或 `surface_habit` 的假设
- **禁止挑战 `identity_anchor`**，谨慎挑战 `hard_constraint`（必须证明收益）
- 只打破1个假设，其他全部遵守品类骨架+品牌语法
- 必须通过安全阀（6项全通过才能保留）：
  1. 挑战后用户3秒内还能认出这是该品类吗？
  2. 核心功能没有变弱吗？
  3. 用户原有操作动作仍然成立吗？
  4. 仍符合品牌语法吗？
  5. 挑战后用户体验明显变好吗？
  6. 只挑战了一个假设吗？

### 6种方法完整性自检

16个概念生成完后，必须自检：
| 方法 | 要求数量 | 实际数量 | ✅/❌ |
|------|----------|----------|------|
| 单策略深挖 | 4 | | |
| 策略交叉 | 4 | | |
| 反向激进 | 2 | | |
| 细节拼接 | 2 | | |
| Wildcard | 2 | | |
| 品类假设挑战 | 2 | | |

任何方法实际数量=0 → 必须补足。不允许省略任何一种方法。

### 概念灵感来源多样性检查

16个概念的source_references汇总后：
- 引用的DNA卡 ≥ 8张不同的卡（不能16个概念都指向同一张图）
- 引用的品牌 ≥ 3个不同品牌
- 不满足 → 替换引用最集中的概念，用不同灵感来源重新生成

**每个概念必须有统一设计动词**：
```yaml
design_verb: "shield"  # compress/brace/shield/float/wrap/lock/split/tension
```
所有借来的细节和造型决策必须服务同一个动词。

**每个概念必须包含**：
```yaml
concept_id: "C-01"
source_strategy: "S-01"          # Wildcard标注"wildcard"
source_references: ["RD-2024-0847"]
generation_method: "单策略深挖/策略交叉/反向激进/wildcard"

form_definition:
  base_form: "品牌DNA绿灯表范围内的基础形态"
  hero_feature: "单一视觉主特征（14字内）"
  functional_alibi: "工程/功能硬理由"
  how_it_solves: "用户看到时如何理解它解决了痛点"

visual_test_pass: "是否通过visual_test"
render_anchor:
  primary_reference_image: "product_id（素材索引中的产品ID）"
  delta_from_reference: "和参考图的差异"
```

**使用场景约束检查**：
每个概念必须逐条回应 Step 04 的 form_factor_constraints.must_have 清单。未回应的约束标注[UNMET]，累计2个以上[UNMET]的概念不允许进入评审。

**品类谱系定位检查**：
- 核心区/延伸区内：正常通过
- 超出延伸区：只允许作为边界概念，14个中最多3个

### 评审角色体系说明
- 6个固定角色（品牌守门人、用户理解者、工业设计师、制造工程师、成本经理、渠道代表）
- 1个条件角色：品类专家（按品类动态匹配）
- 视觉总监：第0轮快筛（预评审，不计入8角色评分）+ 后续轮次有否决权
- 第0轮快筛是预评审，不计入正式评分。8角色正式评审从第1轮开始。

### 【R2强制】枚举值Schema（防止发明非法值）

本步骤所有枚举字段仅限以下合法值，超出即无效：
| 字段 | 合法值 | 非法值举例（直接FAIL自检） |
|------|--------|--------------------------|
| 8角色评分结论 verdict | PASS / FAIL | CONDITIONAL / PARTIAL / WEAK_PASS / PASS_PREDICTED |
| Pugh维度评分 | 1 / 2 / 3 / 4 / 5（整数） | 3.5 / "中" / MEDIUM |
| F25 overall_verdict | PASS / FAIL | CONDITIONAL_PASS / PARTIAL |
| 自检状态 | ✅ / ❌ | PARTIAL / TBD / N/A |
| visual_object_valid | true / false | PARTIAL / INVALID_VISUAL |
| migration_validation result | PASS / FAIL | CONDITIONAL |
| 硬杀触发 | TRIGGERED / NOT_TRIGGERED | YELLOW / PARTIAL |

**发现非法枚举值** → 自检该项强制标 ❌，不允许继续进入下一步。

### Pugh评分独立性规则（防止AI自评全高分）

8角色评分必须分步执行，不能一次性输出所有角色的分数：
1. 每个角色独立评分，只基于自己的评审焦点，不看其他角色的分数
2. 评分时必须附≤20字理由
3. 全部角色评完后再汇总

**交叉校验（汇总后必须检查）**：
- 如果某概念所有维度均≥4分 → 必须回答"哪个维度最弱？为什么仍给4分？"
- 如果冠军候选的某维度分数 > 另一概念，但实际描述中另一概念在该维度更强 → 重新评估该维度
- 记忆度评分必须和"最终总览"中的记忆点描述一致。不允许Pugh打5分但总览说另一个"记忆最强"
- 品牌距离评分必须附"和品牌哪款现有产品最接近，造型上具体哪里像哪里不像"

### 阶段B+：低保真草图锁定（视觉评分前强制步骤）

**【R4强制】在进入8角色评审之前，16个概念必须先有视觉对象。**

视觉评分（轮廓记忆点/拼接感/品牌距离）不能凭文字描述打分——必须基于视觉对象。

**低保真草图生成规则**：
- 形式：文字几何描述（"正面矩形，左侧竖向凸出散热条，右侧圆形显示屏"）+ 手绘风格ASCII示意图，或提供给图像AI的简化生成提示词
- 每个概念最低要求：正视图轮廓描述 + 主特征位置标注 + 比例关系描述（如"宽高比约3:2，主特征占正面面积40%"）
- 达标判断：视觉总监读完描述后，能够凭想象"看见"这个产品的轮廓
- **不达标的概念**：视觉总监快筛阶段标为`INVALID_VISUAL`，不得打分，只能回生成阶段重写视觉描述
- **全部概念均INVALID_VISUAL**：回Step 03重选方向，或放宽视觉描述要求（明确哪个层级的视觉证据是底线）

```yaml
sketch_status:
  concept_id: ""
  visual_description_present: true/false     # 有无视觉对象描述
  silhouette_described: true/false           # 外轮廓是否描述
  hero_feature_located: true/false           # 主特征位置是否标注
  proportion_stated: true/false              # 比例关系是否说明
  visual_object_valid: true/false            # 是否达到视觉评分最低要求
```

只有`visual_object_valid: true`的概念才能进入8角色评审。

### 阶段C：8角色评审（后台）

**8个评审角色**（6个固定 + 1个品类专家 + 1个视觉总监）：

| 角色 | 评审焦点 | 典型问题 |
|------|----------|----------|
| 品牌守门人 | 品牌合规 | "这个造型在客户现有产品线里违和吗？" |
| 用户理解者 | 需求回应 | "消费者3秒内能理解这个造型想表达什么吗？" |
| 工业设计师 | 造型质量 | "Hero Feature够强吗？去掉它产品还有记忆点吗？" |
| 制造工程师 | 可制造性 | "这个分件怎么做？模具费多少？良率多少？" |
| 成本经理 | 成本可控 | "BOM在走廊内吗？哪里最可能超？" |
| 渠道代表 | 市场接受 | "现有渠道能直接卖吗？需要教育市场吗？" |

**评审流程**（3轮）：

**第0轮：视觉总监快筛**（V4.3新增，在正式评审前先杀掉明显不行的）
视觉总监只看5个问题，任一不通过直接淘汰：
- 轮廓有没有记忆点？
- 主次关系清不清楚？
- 有没有廉价拼接感？
- 比例像不像该品类？
- 设计动词是否统一？

第1轮：8角色各打分（1-5），每个角色必须附一句话理由（≤20字）。淘汰总分<2.5或任一角色<2的概念。品牌红线触犯直接替换。

第2轮：对存活概念，8角色各提一个最担心的问题。有致命问题的淘汰或修正。

第3轮：最终排序。淘汰规则：总分<2.5、任一角色<2、品牌红线触犯、视觉总监否决。存活概念中按总分排序，选出 **8个概念** 输出给用户。如存活不足8个，从淘汰概念中选最接近阈值的补位并标注风险。

**第7个角色：品类专家（Conditional）**

6个通用角色之外，根据品类动态增加1个品类专家：

```
户外灯具 → 品类专家关注：配光/防水IP/散热/安装方式/维护通道
室内灯具 → 品类专家关注：眩光控制/调光兼容/天花板适配/布线隐藏
家具 → 品类专家关注：人体工学/结构稳定/表面耐久/空间适配
小家电 → 品类专家关注：操作路径/清洁维护/安全/模具拆件
儿童产品 → 品类专家关注：安全边界/误用防护/情绪接受度/家长购买理由
```

**第8个角色：设计师人格补充（Optional）**

根据项目特征，从 `.claude/knowledge/设计师人格库.md` 中选取2-3个人格作为补充评审视角：
- 高端消费品项目 → 选 Jonathan Ive(02) + Naoto Fukasawa(04)
- 工业/工具品类 → 选 Dieter Rams(01) + DfA/DFMA(18)
- 激进创新项目 → 选 Philippe Starck(28) + Gaetano Pesce(30)
选取的人格在第2轮提出该人格视角下的最大担忧。

### 阶段D：购买句验证 + 用户选择 + Pugh硬杀

#### 购买句验证（硬门槛，每个概念必须通过）

每个概念必须能说出一句客户愿意拿去卖的话：

```
"我们这款产品比普通产品更____，因为你一眼能看到____。"
```

说不出来 → 概念没有商业抓手 → 淘汰或重写。

#### 用户选择

**用户从8个中选6个** → 系统对6个执行 F15 Pugh矩阵：

**Pugh 7维度**（权重）：
1. 3秒记忆度（25%）
2. 品牌/渠道接受度（20%）
3. 功能卖点清晰度（15%）
4. 制造可行性（15%）
5. 成本可控性（10%）
6. 平台复用率（5%）
7. 合规风险（10%）

**硬杀规则**（触发即退回重生）：
- 品牌/渠道接受度 < 3分
- BOM超成本走廊 >10% 且无3条以内降本路径
- 3秒记忆度 < 2分

**Wildcard与突破保护的优先级**：
Wildcard限制优先于突破保护规则。满足突破保护条件的Wildcard可保留为边界款2，但仍受"Wildcard最多1个"限制。

#### 5方案角色分配（每个方案有明确市场角色）

| 角色 | 定位 | 选择标准 |
|------|------|----------|
| **冠军款** | 最有可能让客户一次选中 | Pugh最高分 |
| **安全款1** | 最接近客户现有产品线，低决策风险 | 品牌接受度最高 |
| **安全款2** | 成本/制造最稳，适合大批量 | 成本+制造可行性最高 |
| **边界款1** | 品牌可接受范围内的新意 | 在延伸区内，视觉差异化高 |
| **边界款2** | 试探客户未来方向 | 最接近延伸区边缘 |

**Wildcard限制**：最终5方案中，Wildcard最多保留1个，细节拼接最多保留1个。冠军方案不能来自纯Wildcard。

**突破方案保护规则**（防止Pugh压制有杀伤力的方案）：
如果某方案同时满足以下3条，不能被Pugh总分直接淘汰，必须进入边界款候选：
1. 视觉记忆点 ≥ 4分（8角色评审中视觉总监评分）
2. 品牌距离 ≥ 3分
3. 制造风险可解释（有降本/替代工艺路径）

冠军必须额外回答：
1. 为什么比第二名更容易成交？
2. 客户最可能因为什么否掉它？
3. 购买句是什么？

### 被淘汰概念即时入反例库
Pugh硬杀掉的概念，当场提取失败因素写入反例库：
```yaml
anti_id: "ANTI-{项目编号}-{概念编号}"
source: "本项目概念{concept_id}"
what_not_to_do: "{被杀原因}"
why_dangerous: "{Pugh哪个维度不达标}"
applies_to: "{品类/品牌}"
```
不等Step 10，立即写入 `.claude/knowledge/反例库/`。

### 失败回退路径
- **全部16概念被第0轮快筛淘汰**：回到Step 03重新选方向，或扩大品牌创新半径后重新生成。不能在当前方向上死磕。
- **用户从8个中选不出6个**：系统从剩余淘汰概念中补充到8个重新呈现，或回到Step 04补充灵感来源后重新生成。

### F14 覆盖矩阵检查
最终5个概念必须覆盖（此为执行标准，覆盖框架库F14定义）：
- 至少3种不同的主视觉特征（对应框架库"语义方向覆盖"）
- 至少2个不同的BOM档位（对应框架库"成本档覆盖"）
- 至少2条不同的造型策略来源（对应框架库"结构路径覆盖"）
- **每个概念至少有1张有图DNA卡作为主锚点**（知识参照卡不算）
不满足 → 替换重复度最高的

### 品牌红线传递检查（每个概念必答）
1. 这个设计有没有违反品牌红线？
2. 有没有为了创新而扩大客户创新半径？
3. 有没有出现客户品牌从未使用过的视觉语言？
4. 有没有让产品看起来像另一个品牌？

### 【R12】痛点全覆盖检查（5方案角色分配前必做）

Step 03识别的所有PP-XX痛点必须在5方案中有至少一个概念回应：

```yaml
pain_point_coverage:
  - id: "PP-01"
    pain_point: ""
    addressed_by: ["C-01", "C-03"]    # 哪个方案回应了这个痛点
    coverage_verdict: "COVERED / NOT_COVERED"
    note: ""    # NOT_COVERED时必须说明原因
```

存在未覆盖的PP-XX且无说明理由 → 不能进入Step 06，回生成阶段补概念。

## 输出流程
1. 阶段A造型策略展开 → **等用户确认**
2. 后台执行阶段B+C → 输出8张钩子卡
3. **用户选6个** → 购买句验证 → Pugh硬杀 → 分配角色 → 确认5个进入深化

```yaml

hard_sell_point: "唯一硬卖点（18字内）"
purchase_sentence: "我们这款产品比普通产品更____，因为你一眼能看到____"
first_glance_10m: "10米外看到什么"
solves_what: "解决用户什么痛苦"
why_this_brand: "为什么像这个品牌的"
sacrifice: "主动放弃了什么"
render_anchor: "渲染参考图编号"
```
