# 模拟用户角色库（已废弃）

模拟审计的核心是用真实的用户行为去踢工作流的轮胎。角色不是理想化的完美用户，而是带着真实人类缺点的人——会犯懒、会不耐烦、会看不懂、会跳步。

---

## 角色A：资深设计师

**经验**：5年+，熟悉灯具品类和OEM流程，做过几十个项目

**行为特征**：
- 流程跑得快，跳过自己觉得不必要的步骤
- 对废话零容忍——看到"根据您的需求，我们可以考虑以下方向"这类话会直接翻白眼
- 不需要引导，知道自己要什么
- 会主动挑战系统输出的质量，不会无脑接受
- 更在意输出的专业深度而不是格式好不好看

**关注点**：输出深度、方案差异化真实性、落地可行性

**典型反应**：
1. "这个竞品分析太浅了，只列了名字没有洞察"
2. "这10个方案里有7个本质上是同一个思路"
3. "这个DFM判定是怎么PASS的？这明显开不了模"
4. "别问我了，直接给方案"
5. "这段分析换个品类也能用，等于没说"

**暴露的问题类型**：
- 输出深度不够（分析浮在表面，缺乏行业洞察）
- 方案同质化（看似10个方案实则2-3个思路的变体）
- 分析流于表面（套话多、干货少）
- DFM/落地性判断不严谨

## 角色B：初级设计师

**经验**：1年，对工作流不熟悉，刚接触AI辅助设计

**行为特征**：
- 不确定每步该做什么，需要清晰引导
- 看到工作流专属术语会困惑（如"MCQ-3消歧"、"状态卡"、"强制断点"）
- 不敢乱点，怕做错
- 倾向于把系统当搜索引擎用，不理解流程的完整逻辑
- 对输出内容缺乏判断力——系统给什么都觉得"好像可以"

**关注点**：引导是否清楚、输出是否看得懂、下一步是否明确

**典型反应**：
1. "状态卡是什么？我该填哪里？"
2. "MCQ-3消歧是什么意思？"
3. "这段话我看不懂在说什么"
4. "接下来我该做什么？"
5. "这个选项有什么区别？我怎么选？"

**暴露的问题类型**：
- 引导不足（用户不知道下一步是什么）
- 术语过多（工作流内部术语没有解释就直接用）
- 交互不直觉（选项含义不清、操作路径不明显）
- 错误恢复困难（做错了不知道怎么退回来）

## 角色C：赶工设计师

**经验**：3年+，能力够但时间紧迫

**行为特征**：
- 想跳步——"前面那些分析我都知道，直接到方案"
- 想快速拿到结果，对任何"多余"的确认极度不耐烦
- 不看中间过程，只看最终输出
- 会故意跳过步骤测试系统的容错
- 对反复确认对话框有生理性厌恶

**关注点**：步骤是否多余、确认是否过多、能不能直接拿到可用输出

**典型反应**：
1. "为什么又要我确认？直接给我方案"
2. "我不需要看这些中间过程"
3. "这个步骤能跳过吗？"
4. "太慢了，我只有2小时"
5. "给我最终结果就行，不要过程"

**暴露的问题类型**：
- 步骤冗余（有些步骤对结果没有实质贡献）
- 确认过多（不需要用户确认的地方反复询问）
- 交互效率低（到可用输出的轮次过多）
- 跳步后信息缺失处理不当（缺关键输入时的回退策略）

## 角色扩展规则

当满足以下条件时，可新增角色：
1. 审计日志中某类问题反复出现（≥3次），但现有角色的行为特征无法自然触发这类问题
2. 出现新的用户场景（如跨部门协作、远程评审）现有角色无法覆盖

**新增角色必须包含**：
- 经验描述
- 行为特征（至少4条）
- 关注点
- 典型反应（5个，必须像真人说话）
- 暴露的问题类型

**限制**：
- 角色总数不超过5个
- 新角色不能和现有角色行为特征高度重叠
- 角色行为必须真实——不是理想化的完美用户
