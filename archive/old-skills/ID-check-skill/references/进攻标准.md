# 进攻标准（Offensive Standards）v1.0

## 定位

本文件定义审计系统的"进攻标准"——检查工业设计工作流的输出有没有在产出好东西。

它与"防守标准"互补：
- 防守标准：系统有没有犯错（丢约束、伪差异化、泛化、偷懒）
- 进攻标准：系统有没有产出具备爆款潜力的关键决策

进攻标准的核心公理来自创造力研究的标准定义：**好 = 原创性 × 有效性**。任何一项为零，整体为零。

---

## 标准一：决策核（Decision Kernel）

**来源**：iPhone全触控范式 / Dyson恒定吸力 / Nespresso体验封装 / Walkman场景迁移

**检查什么**：方案里有没有一个"不可替代的关键决策"——去掉它，方案就不成立或显著降级。

**判定规则**：
- 方案必须明确写出1个关键决策，用一句话表述
- 必须通过反事实测试：去掉这个决策后，方案是否仍然成立？如果仍然成立，说明它不是关键决策
- 必须说明这个决策牺牲了什么（任何好决策都有代价，没有代价的决策不是决策）

**必填字段**：
```
decision_kernel: [一句话描述关键决策]
counterfactual_test: [去掉它之后方案会怎样]
what_is_sacrificed: [为了这个决策放弃了什么]
```

**不合格的典型表现**：
- 方案列了10个卖点但没有一个是"去掉就崩"的
- 关键决策写的是"采用人体工学设计"这种空话
- 反事实测试是"去掉后体验会稍差"而不是"去掉后方案失效"

## 标准二：行业矛盾消解（Industry Contradiction Resolution）

**来源**：Dyson（吸力衰减矛盾）/ TRIZ矛盾消解理论 / Cybertruck（强度vs重量）/ 三星DVD拾取器

**检查什么**：方案有没有识别出行业默认接受的妥协点，并用结构创新消灭它，而不是在中间值折中。

**判定规则**：
- 必须明确写出当前品类中存在的核心矛盾（A和B不可兼得）
- 必须说明行业当前的默认妥协方式是什么
- 必须说明方案用什么机制消解了这个矛盾（不是折中，是消灭）
- 消解机制必须到物理/结构/工程层面，不能只是文字游戏

**必填字段**：
```
core_contradiction: [A vs B，具体描述]
industry_default_tradeoff: [行业目前怎么妥协的]
resolution_mechanism: [方案用什么机制消灭了这个矛盾]
resolution_level: [零件级 / 结构级 / 物理效应级 / 范式级]
```

**不合格的典型表现**：
- 矛盾描述是"好看vs好用"这种泛泛表述
- 消解方式是"平衡两者"而不是"消灭矛盾"
- 分辨率停在零件替换级别（只换了个材料），没有到结构级或更高

**进攻加分规则**：
- 分辨率达到"物理效应级"或"范式级"（如Dyson从孔隙过滤跃迁到离心分离），触发最高进攻加分

## 标准三：跨域迁移（Cross-Domain Transfer）

**来源**：Dyson（锯木厂气旋→家用）/ Anglepoise（汽车悬挂弹簧→台灯）/ OXO（汽车工业TPR→削皮器）/ NeoNurture（汽车零件→婴儿恒温箱）/ Koestler双联想理论 / Uzzi新旧组合研究

**检查什么**：方案的核心机制有没有从其他领域迁移过来，而不是在本品类内部修修补补。

**判定规则**：
- 方案必须列出至少1个跨域迁移链：源领域→迁移的机制/原理/材料/结构→在目标品类中如何落地
- 迁移不能只是类比修辞（"像汽车一样坚固"），必须是实际的结构/机制/材料移植
- 必须说明迁移成立的原因和迁移的风险

**必填字段**：
```
source_domain: [机制来自哪个领域]
transferred_mechanism: [具体迁移了什么]
adaptation_in_target: [在目标品类中怎么落地的]
why_it_works: [迁移为什么成立]
transfer_risk: [迁移可能失败的点]
```

**新旧配比检查**（来自Uzzi研究）：
- 方案必须同时包含"熟悉锚点"（用户已懂的部分）和"新奇变量"（用户没见过的部分）
- 必须解释两者如何耦合
- 如果全是新的，用户无法理解；如果全是旧的，没有差异化

**补充字段**：
```
conventional_anchors: [用户已熟悉的部分]
novel_intrusion: [用户没见过的新变量]
coupling_explanation: [新旧如何耦合成一个整体]
```

**不合格的典型表现**：
- 所有方案的核心机制都来自本品类内部
- 跨域迁移只停留在外观灵感（"灵感来自建筑"）而不是结构/机制层
- 新旧配比失衡——全新到用户看不懂，或全旧只是换了外壳

## 标准四：核心组件剥离（Subtractive Innovation）

**来源**：Walkman（去录音功能）/ Cybertruck（去冲压和喷漆）/ Swatch（51个零件）/ Dieter Rams（少即是多）

**检查什么**：方案有没有通过大胆去除行业默认存在的组件/工序/功能，换取另一个维度的飞跃。

**判定规则**：
- 必须对照品类标准BOM/功能清单，指出方案删除了什么
- 必须说明删除带来了什么维度的提升（重量/体积/成本/强度/便携等）
- 删除不能是偷工减料，必须有逻辑支撑（删除后通过什么替代机制维持原有价值）

**必填字段**：
```
removed_component: [删除了什么行业默认组件/功能/工序]
removal_justification: [为什么可以删]
dimension_gained: [删除后哪个维度获得了飞跃]
alternative_mechanism: [用什么替代机制维持原有价值]
```

**不合格的典型表现**：
- 方案只做加法，从不做减法
- 删除的是无关紧要的东西（去掉了说明书）
- 删除没有带来任何维度的实质提升

## 标准五：极端用户驱动（Extreme User as Design Driver）

**来源**：OXO（关节炎用户）/ Nest（零专业知识用户自行安装）/ Roomba（零维护能力用户）/ 深泽直人（无意识行为）

**检查什么**：方案有没有用最苛刻的用户场景定义设计标准，而不是只对"正常用户"做优化。

**判定规则**：
- 必须定义至少1个极端用户画像（能力边界/环境极限/认知限制）
- 必须定义该极端用户在目标场景下的"任务成功判据"
- 方案必须能让极端用户完成任务，并且这个优化同时提升了普通用户的体验

**必填字段**：
```
extreme_user_profile: [谁？什么限制？]
task_success_criteria: [极端用户完成任务的判定标准]
design_response: [方案怎么满足这个极端需求的]
mainstream_benefit: [这个设计同时怎么提升了普通用户的体验]
```

**行为脚本要求**（来自深泽直人方法论）：
- 必须提供至少3段行为脚本（手怎么动、眼怎么看、身体什么姿势）
- 每段脚本标注摩擦点和方案的消除策略
- 如果摩擦消除只停在UI/外观层，没有物理结构变更，降级

**补充字段**：
```
behavior_scripts: [至少3段，含具体动作描述]
friction_points: [每段脚本中的摩擦点]
design_responses: [方案怎么消除这些摩擦的，到什么层级]
```

## 标准六：系统闭环与时间价值（System Loop & Time-to-Value）

**来源**：iPod+iTunes / Kindle / Philips Hue / Nespresso / GoPro

**检查什么**：方案是不是一个孤立产品，还是一个端到端的价值交付系统。

**判定规则**：
- 如果产品价值依赖生态/服务/耗材/内容，必须给出端到端旅程分解
- 必须识别旅程中摩擦最大的1-2个环节，并说明方案怎么消灭它们
- 必须给出time-to-value指标：用户从拿到产品到获得核心价值的时间

**必填字段**：
```
end_to_end_journey: [从获取到长期使用的每一步]
top_friction_points: [旅程中摩擦最大的1-2个环节]
friction_elimination: [方案怎么消灭这些摩擦的]
time_to_value: [用户到达核心价值的最短路径和预估时间]
system_boundary: [哪些环节由我控制，哪些开放给生态]
```

**不合格的典型表现**：
- 方案只关注产品本体，不考虑购买/安装/学习/维护/复购
- time-to-value没有量化（"很快就能上手"是空话）
- 声称有生态但没有具体的扩展点定义

## 标准七：制造架构即战略（Manufacturing as Strategy）

**来源**：Swatch（51零件/不可维修/零缺陷自动化）/ Cybertruck（外骨骼/去冲压喷漆）/ Dyson（5127原型的迭代方法学）

**检查什么**：方案的制造架构有没有被当成战略武器来设计，而不是"设计完了交给工厂"。

**判定规则**：
- 必须说明方案的成本结构被什么变量支配
- 必须说明方案的架构简化指标（零件数/工序数/装配方式）相对行业基准的变化
- 必须说明架构变化如何导致了体验/定位的变化

**必填字段**：
```
cost_structure_driver: [成本被什么变量支配]
architecture_simplification: [零件数/工序/装配方式 vs 行业基准]
architecture_to_experience: [架构变化如何导致了体验/定位变化]
```

**迭代与验证要求**（来自Dyson方法学/Aeron研究型判据）：
- 必须有验证计划和可能的失败模式预判
- 必须有至少两轮迭代假设（如果第一版失败，往什么方向迭代）

**补充字段**：
```
validation_plan: [怎么验证这个方案能做出来]
failure_modes: [最可能失败的点]
iteration_hypothesis: [失败后往什么方向迭代]
```

## 反模式防御（Anti-patterns）

以下是AI执行进攻标准时必须遵守的禁令，防止审计本身偷懒：

**禁止走马观花**：所有判断必须锚定到具体的组件、结构、材料、交互层，不允许泛泛评论。

**禁止过度挑剔细节**：进攻标准的计算力必须集中在核心架构决策上，不允许把主要精力花在边缘美学修饰。

**禁止无备选的阻断**：如果审计判定方案缺乏进攻性，必须基于跨域迁移、TRIZ原理或减法思维提出至少1个"相邻可能"的替代方向。不允许只说"不够好"不说"可以往哪里走"。

**禁止推翻重来**：不允许脱离当前方案的成本、制造、品类约束去幻想理想化设计。所有进攻标准的判定和建议都必须在现实约束内。

**禁止审美形容词充数**：任何进攻得分的理由中，不允许使用"高级感""科技感""简约感""品质感"等无法转译为几何/结构/材料特征的形容词。

## 降级方案：苏格拉底式追问

当AI无法直接判定某个进攻标准（比如无法评估跨域迁移的物理可行性），不要硬打分，转为向设计师追问：

- "你的核心物理传动机制，是否借鉴了重工或自然界的非相关现象？请描述具体映射路径。"
- "请阐述为了实现当前的形态，你从品类默认标准中剥离了哪项组件？"
- "你声称的差异化，在竞品 [具体竞品名] 中是否已经存在？请给出对比。"
- "如果去掉你的关键决策，方案是否仍然成立？请做反事实分析。"

追问后，根据设计师回答的逻辑闭环度和证据密度来判定进攻得分。

## 评分层级

进攻标准采用两层评分：

**第一层：硬字段齐全度（可客观检查）**
- 7个标准中，每个标准的必填字段是否被完整填写
- 字段内容是否满足判定规则（不是空话、有具体内容、通过品类替换测试）
- 满分100，每个标准占比相同

**第二层：决策质量评分（CAT式评判）**
- 在硬字段齐全的基础上，评判决策核的不可替代性、矛盾消解的彻底性、跨域迁移的创造性
- 评分必须引用硬字段内容来解释分数，不允许用审美形容词
- 满分100

**最终进攻得分 = 硬字段齐全度 × 决策质量评分 / 100**

如果硬字段齐全度为0，无论决策质量多高，最终进攻得分都是0。
如果决策质量为0，无论字段多齐全，最终进攻得分也是0。

这与创造力的核心公理一致：**原创性 × 有效性，任何一项为零，整体为零。**
