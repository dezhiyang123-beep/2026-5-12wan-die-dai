# 体验审计标准（精简版）

> 本文件定位：整链路验收（第三层审计）的补充检查维度。主力审计由防守标准+进攻标准+节点攻击脚本承担。

---

## 7个维度速查

| 维度 | 核心问题 | 不合格信号 |
|------|----------|-----------|
| **一、交互效率** | 到可用输出经历了多少轮，有多少轮是必要的？ | 冗余确认≥3轮；废话轮次存在；确认循环卡住用户 |
| **二、输出可用度** | 输出能不能直接拿去用？ | 关键参数缺失；"待补充"占位符；笼统方向性描述 |
| **三、理解深度** | 分析是否到位，还是表面应付？ | 换品类仍成立；套话充数；竞品只列名字无洞察 |
| **四、信息连贯性** | 约束从A到H有没有丢失或变形？ | 预算丢失；风格漂移；中途变更后未更新 |
| **五、引导清晰度** | 用户随时知道该做什么吗？ | 术语未解释；选项区别不清；出错无恢复路径 |
| **六、方案差异化真实性** | 方案间差异是真的还是换皮？ | 50%+同构；差异只在CMF；命名夸大实际差异 |
| **七、落地可信度** | 方案能真正做出来吗？ | 无具体参数；违反工程原则；成本明显超标 |

---

## 维度一：交互效率

**核心检查**：冗余确认、废话轮次、重复信息
**判定**：S1=1-2轮可省 / S2=3轮+冗余 / S3=确认循环卡住

## 维度二：输出可用度

**核心检查**：格式完整、数值具体、可直接进入下一步
**判定**：S1=微调格式 / S2=关键参数缺失 / S3=完全不可用

## 维度三：理解深度

**核心检查**：竞品洞察、需求核心诉求、逻辑链完整、品类专业性
**判定**：S1=缺1-2维度 / S2=表面套话 / S3=无实质内容

## 维度四：信息连贯性

**核心检查**：约束传递、品牌调性一致、节点交接完整、变更同步
**判定**：S1=非核心丢失 / S2=重要约束忽略 / S3=核心约束丢失

## 维度五：引导清晰度

**核心检查**：输入提示明确、术语解释、选项可辨、恢复路径、进度感知
**判定**：S1=个别术语未释 / S2=步骤不确定 / S3=完全卡住

## 维度六：方案差异化真实性

**核心检查**：核心结构差异、用户可感知、设计空间覆盖、命名真实性
**判定**：S1=1-2个偏表面 / S2=多数同构 / S3=全部同一思路

## 维度七：落地可信度

**核心检查**：结构可行、材料合理、工艺具体、成本合理、认证考虑
**判定**：S1=个别参数缺 / S2=笼统不可判 / S3=违反工程原则
