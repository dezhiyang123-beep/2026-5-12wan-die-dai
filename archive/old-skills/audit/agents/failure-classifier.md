# Failure Classifier

> 本模块负责对压测中发现的每个问题做根因定位，使用双轴诊断模型输出结构化归因结果。
> 由主审计（Claude 本身）在汇总阶段执行，不委托给 subagent。

---

## 参考文件与接口

**输入来源：**
- Node Observer 旁注日志（节点状态变化表 + 断点记录表）
- pm-simulator.md Transcript Compiler 输出的完整对话流
- 压测汇总报告中的运行时问题列表（步骤3输出）

**输出目标：** `rule-patch-writer.md`（结构化问题矩阵）

---

## 双轴诊断模型

### 轴 1：发生层（问题在哪一层触发）

| 层级 | 名称 | 说明 |
|------|------|------|
| L1 | 输入层 | 用户输入缺失、格式错误、歧义未被捕获 |
| L2 | 路由层 | Skill 选择错误、前置条件判断失误、分支路径错误 |
| L3 | 规则层 | 规则本身存在缺陷（缺失/冲突/歧义/失效/越权） |
| L4 | 状态层 | 跨节点状态传递丢失、字段未持久化、上下文断裂 |
| L5 | 交付层 | 输出格式错误、内容不完整、与预期模板不符 |

### 轴 2：问题性质（问题属于哪类规则缺陷）

| 类型 | 名称 | 说明 |
|------|------|------|
| N1 | 规则缺失 | 该场景无对应规则覆盖，系统无法处理 |
| N2 | 规则冲突 | 两条或多条规则在同一场景下给出矛盾指令 |
| N3 | 规则歧义 | 规则表述模糊，执行者可做多种解读 |
| N4 | 规则失效 | 规则存在但在特定条件下不生效或被绕过 |
| N5 | 规则越权 | 规则执行范围超出预期，干扰其他模块逻辑 |

## 输出字段（每个问题必须包含以下全部字段）

```
问题ID：        [P[级别]-[节点]-[序号]，如 P0-A-001 / P1-D-002]
                规则：级别=P0/P1/P2；节点=首次暴露节点字母(A-G)；序号=同节点内自增，从001开始
问题表象：      [一句话描述用户或节点观察到的异常行为]
首次暴露节点：  [@@ITER 编号 或 Skill名+步骤]
根因层级(轴1)： [L1~L5 + 层名称]
问题性质(轴2)： [N1~N5 + 类型名称]
影响节点：      [列出受影响的所有 Skill 或步骤]
优先级：        [P0 / P1 / P2]
修复策略类型：  [见 references/failure-taxonomy.md 第五章，可多选，用"+"连接]
```

## 操作规则

1. **双轴必填**：每个问题必须同时标注轴1（L1-L5）和轴2（N1-N5），不得只填其一
2. **仅结构化输出**：不输出自由文本归因段落，所有字段按模板填写
3. **不跳过轴定位**：即使问题表象明显，仍须完整执行双轴定位，不得以"显而易见"为由省略
4. **多轴场景处理**：若一个问题涉及多层，记录首要触发层为轴1，在"影响节点"中注明次要层
5. **修复策略可多选**：一个问题可对应多种修复策略类型，用"+"连接
