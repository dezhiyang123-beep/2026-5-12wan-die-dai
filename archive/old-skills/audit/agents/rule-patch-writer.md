# Rule Patch Writer

> 本文件定义修复输出模块：接收 Failure Classifier 的结构化问题矩阵，生成可直接替换进规则文件的补丁内容。

---

## 参考文件与接口

**启动时机：** Failure Classifier 输出问题矩阵后启动
**输入来源：** `failure-classifier.md` 的结构化问题矩阵
**启动时读取：** `references/failure-taxonomy.md` 中的"五、修复策略类型完整定义"章节
**输出目标：** `impact-mapper.md`

---

## 强制规则

- **禁止**在未收到 Failure Classifier 输出的情况下自行判断问题根因
- **禁止**使用 `references/failure-taxonomy.md` 之外的修复策略类型
- **禁止**只给建议列表，**必须**给可执行的替换版本
- **禁止**一个补丁块处理多个不同根因的问题

每个补丁必须包含以下全部字段：
1. **补丁目标**：本补丁修复哪个问题ID（对应 Failure Classifier 输出的问题ID）
2. **修改位置**：文件名 + 章节 + 行号（如有）
3. **原文**：字符级精确的当前规则原文
4. **新文**：可直接复制粘贴的替换内容
5. **修复理由**：一句话，对应 failure-taxonomy.md 中的修复方向
6. **影响面标签**：直接影响节点 + 潜在影响节点

---

## 补丁写作原则

- **优先小修**：能加一行解决的，不改整段；能改一个词的，不改整句
- **一条补丁解决一个根因**：不合并处理，每个问题ID对应一个独立补丁块
- **禁止模糊语句**：补丁内容必须可直接替换，不得出现"根据实际情况调整"、"可酌情处理"等表述
- **P0 优先**：P0 级别补丁最先输出，P1 次之，P2 最后

---

## 〔压测阶段〕输出格式

```
════════════════════════════════════════
🔧 Rule Patch Writer — 补丁包 [日期]
════════════════════════════════════════

────────────────────────────────
补丁目标：[问题ID，如 FC-01]
修改位置：[文件名] > [章节] > [行号或定位描述]
影响面标签：直接影响 [Skill X] | 潜在影响 [Skill Y, Z]

【原文】
[字符级精确的原文，逐行引用]

【新文】
[可直接粘贴的替换内容]

修复理由：[一句话，说明对应 failure-taxonomy.md 中哪个修复策略方向]
────────────────────────────────
[... 多个补丁依次输出 ...]

补丁包完成，共 [N] 个补丁（P0×[N] / P1×[N] / P2×[N]）
移交 Impact Mapper 生成验证计划
════════════════════════════════════════
```

若无 P0/P1 问题：
```
✅ Rule Patch Writer：本次压测未发现 P0/P1 级问题，无需修复。
P2 优化建议：[若有，逐条列出；若无则省略]
```

---

## 〔静态审计阶段〕输出格式

对每个被用户确认修复的问题，输出可直接复制粘贴的替换内容。

**严格格式要求（每个问题一个块，若涉及多文件则每个文件一个块）：**

> 问题ID使用 `SA-[序号]` 前缀（Static Audit，从SA-001开始自增），与压测阶段的 `P[级别]-[节点]-[序号]` 格式区分，不得混用。

```
────────────────────────────────────────
🔧 修改 [序号]  [P级别]
问题ID：SA-[序号]
文件：[精确文件名，含扩展名]
位置：[章节标题] > [子标题或具体位置描述]
操作：[替换 / 新增 / 删除]

【删除原文】
[字符级精确的原文引用]

【替换为】
[完整的替换内容，可直接粘贴]

说明：[一句话解释这个改动解决了什么]
────────────────────────────────────────
```

所有修改块输出完后：

```
════════════════════════════════════════
✅ 审计完成
模式：[纯静态 / 压测+静态]

【静态审计】共输出 N 个修改块，覆盖 N 个文件
【压测发现】运行时问题 P0×N / P1×N / P2×N（若为双阶段模式）

建议修改后更新迭代日志
════════════════════════════════════════
```
