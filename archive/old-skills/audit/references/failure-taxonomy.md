# 问题归因字典

> 本文件供 Failure Classifier 调用。
> Failure Classifier 接收 Node Observer 的旁注日志和完整对话流，
> 对每个发现的问题执行双轴归因，输出结构化问题矩阵。
> 禁止跳过归因直接给修复建议。

---

## 一、Failure Classifier 执行流程

### 输入

- Node Observer 旁注日志
- PM Simulator 与系统的完整对话流
- @@ITER 记录
- 当前规则文件（技能A-H_vN.md / Instructions_vN.md）

### 执行步骤

**Step 1：问题收集**
从对话流和旁注日志中提取所有异常点，包括：
- 节点卡点（流程无法推进）
- 规则冲突（两条规则矛盾）
- 降级触发（字段被迫标注UNKNOWN或L置信度）
- 隐性假设（未授权的推断被写入状态卡）
- 返工触发（节点被要求重新执行）
- @@ITER 命中记录

**Step 2：逐问题双轴归因**
对每个问题，分别在轴1（发生层）和轴2（问题性质）上定位，
必须同时标注两个轴，缺一不可。

**Step 3：判断优先级**
按 P0/P1/P2 标准判定每个问题的优先级。

**Step 4：判断修复策略类型**
基于双轴归因结果，从修复策略枚举中选择对应类型。

**Step 5：输出结构化问题矩阵**
按标准字段格式输出，交给 Rule Patch Writer。

### 输出格式（每个问题一条）

```
问题ID：[P0/P1/P2]-[节点字母]-[序号]，如 P0-A-001
问题表象：[用户或系统看到的现象，1-2句话]
首次暴露节点：[Skill A/B/C/D/E/F/G]
根因层级（轴1）：[L1输入层 / L2路由层 / L3规则层 / L4状态层 / L5交付层]
问题性质（轴2）：[N1缺失 / N2冲突 / N3歧义 / N4失效 / N5越权]
影响节点：[列出所有受影响的节点]
优先级：[P0 / P1 / P2]
修复策略类型：[从枚举中选择]
规则来源：[具体文件名 + 章节 + 行号（如有）]
```

## 二、轴1：发生层定义

### L1 输入层

**定义：** 用户输入没有被正确吸收、约束或转译，导致后续流程建立在错误的前提上。

**典型表现：**
- 没追问够就推进节点，导致关键字段为空
- 错把用户模糊表达当已确认信息写入状态卡
- MCQ 选项把用户框死，没有跳出空间（如供电方式选项不覆盖固定安装类）
- 没捕捉到用户输入中的否定条件
- 品类大类判断错误导致后续所有品类相关模板跑偏
- 新客户档案字段全为UNKNOWN但没有触发强制暂停

**与其他层的区别：** L1 是"输入进来就错了"，L2 是"输入对了但路由错了"，L3 是"路由对了但规则本身有问题"。

**常见修复策略类型：** 新增规则 / 增加停机条件 / 增加守门校验 / 收紧规则

---

### L2 路由层

**定义：** 应该去哪个节点、该不该停、该不该返工，系统做出了错误判断。

**典型表现：**
- 本该回 B/C 重新确认设计维度，结果硬推进 D
- 本该在新客户情形B暂停，结果静默继续
- 本该触发 @@ITER 记录，结果没有记录
- F 未通过仍继续推进 G/H 且没有标注风险版
- 应该返工的节点被静默跳过
- Skill D强依赖字段为空但没有触发P0警告

**与其他层的区别：** L2 是"走错了路"，不是规则本身有问题，而是路由判断出了错。

**常见修复策略类型：** 增加返工条件 / 增加停机条件 / 收紧规则 / 增加守门校验

---

### L3 规则层

**定义：** 规则本身有问题，导致系统无法正确执行，或执行后产生错误结果。

**典型表现：**
- 某个场景完全没有规则覆盖（缺失）
- 两条规则在某个场景下互相矛盾（冲突）
- 规则描述可以多种解释（歧义）
- 规则存在但在真实运行中被绕过（失效）
- 某条规则影响了不应该影响的节点（越权）

**与其他层的区别：** L3 是"规则本身写错了或没写"，不是执行问题。即使系统完全按规则执行，结果也是错的。

**常见修复策略类型：** 新增规则 / 删除冲突规则 / 拆分规则 / 收紧规则 / 增加输出模板约束

---

### L4 状态层

**定义：** 系统内部状态没有被正确维护，导致后续节点基于错误状态运行。

**典型表现：**
- 已确认/未确认状态标记错误
- 当前版本号错误（如文件名引用旧版本）
- 选定方案状态在节点间传递时丢失
- 造型意图摘要没有同步到下游 GPT Project
- 返工后旧状态没有清除，导致新旧状态并存
- F 队列条目没有被正确推入或清零
- UNKNOWN 字段没有被正确标记进入 F 队列

**与其他层的区别：** L4 是"状态数据本身出错了"，规则和路由都可能是对的，但内部数据不对。

**常见修复策略类型：** 增加状态字段 / 增加守门校验 / 收紧规则

---

### L5 交付层

**定义：** 前面所有节点都跑通了，但最终交付物不可用或不达标。

**典型表现：**
- 效果图提示词包含气质词，GPT Project 无法执行
- 造型意图摘要字段有UNKNOWN，导致GPT出图跑偏
- PPT 某页叙事断裂，老板追问时答不上来
- PRD / CMF / 落地性风险三者之间存在不一致
- L 置信度内容出现在 PPT 正文而非备注
- 最终交付物无法支撑客户提案

**与其他层的区别：** L5 是"过程都对了但结果不能用"，问题在最后一公里。

**常见修复策略类型：** 增加输出模板约束 / 增加守门校验 / 收紧规则

## 三、轴2：问题性质定义

### N1 规则缺失

**定义：** 这个场景在所有规则文件中找不到对应条款，系统无从执行。

**识别方法：** 在规则文件中搜索相关关键词，找不到任何覆盖当前场景的条款。

**典型案例：**
- 固定安装类品类的供电方式MCQ选项完全空白
- 植物灯类品类没有对应的消费洞察人格
- 新客户档案字段全为UNKNOWN时没有优先级区分规则

**修复方向：** 新增规则，必须包含：触发条件、执行动作、预期输出。

---

### N2 规则冲突

**定义：** 两条或多条规则在某个特定场景下同时适用，但要求互相矛盾。

**识别方法：** 能找到两条规则，且在当前场景下两条规则不能同时满足。

**典型案例：**
- "不可触碰约束只放H置信度条目" 与 "供电方式作为核心硬件约束本应是H，却因MCQ覆盖缺口无法填入"
- "Skill F未通过不得出图" 与 "用户坚持继续时标注风险版继续"

**修复方向：** 裁定优先级（明确哪条规则在什么条件下优先），或删除其中一条，或新增仲裁规则。

---

### N3 规则歧义

**定义：** 规则存在且没有冲突，但描述不够精确，可以被合理解读成不同的执行方式。

**识别方法：** 规则文字本身没有明显错误，但面对具体场景时，不同的解读会产生不同的执行结果。

**典型案例：**
- "消费洞察人格从编号22-27中选2条" — 未说明品类不匹配时如何处理
- "顶部输出警告" — 未定义警告的格式和后续动作
- "[ITER]格式固定6行" — 但实际格式块是7行

**修复方向：** 拆分规则，为不同场景分别写明确的执行路径，消除解读空间。

---

### N4 规则失效

**定义：** 规则写了，触发条件也满足了，但在真实运行中被绕过或忽略。

**识别方法：** 能找到对应规则条款，触发条件已满足，但压测记录显示该规则没有被执行。

**典型案例：**
- BUG-07 降级规则存在，但联网取证失败后仍用推断补标H置信度
- 节点确认规则存在，但压测中被"代入默认值继续"替代
- @@ITER 触发规则存在，但迭代观察点命中后没有输出ITER块

**修复方向：** 增加强制触发条件（将"应该"改为"必须"），或增加守门校验（在规则执行后验证结果是否符合预期）。

---

### N5 规则越权

**定义：** 某条规则的作用范围超出本节点或本场景，意外影响了不应该影响的其他节点或状态。

**识别方法：** 规则在本节点执行后，产生了对其他节点的副作用，且这种影响不是预期的。

**典型案例：**
- Skill B 某条规则要求"锁定不可变更项"，但其执行导致 Skill D 的方案生成空间被不合理压缩
- Skill F 的L置信度队列合并规则影响了 Skill G 的执行判断

**修复方向：** 收紧规则的适用范围，明确边界条件，增加"仅在本节点内有效"的限定。

---

## 四、多层问题处理规则

一个问题可能同时涉及多个发生层。处理规则如下：

**当同一问题涉及多层时：**
1. 按发生顺序列出所有涉及的层（如：L1→L3）
2. 优先修复最上游的层（L1 > L2 > L3 > L4 > L5）
3. 分别判断每一层的问题性质（轴2可以不同）
4. 每一层分别输出修复策略类型

**典型多层案例：**
- 新客户档案全UNKNOWN → L1（输入层，MCQ无法正确引导）+ L2（路由层，没有触发强制暂停）+ L3（规则层，情形B提示无优先级区分）
- 供电字段空置影响Skill D → L1（输入层，MCQ覆盖缺口）+ L3（规则层，冲突）+ L4（状态层，空值没有被正确标记）

## 五、修复策略类型完整定义

### 1. 新增规则
**适用：** N1规则缺失
**要求：** 必须包含触发条件、执行动作、预期输出三个部分
**禁止：** 新增规则不得与现有规则产生冲突，新增前必须检查相关章节

### 2. 收紧规则
**适用：** N4规则失效、N5规则越权
**要求：** 将"应该/建议"改为"必须/禁止"，或增加强制验证步骤
**禁止：** 不得收紧到影响正常流程推进

### 3. 拆分规则
**适用：** N3规则歧义
**要求：** 为每个场景分别写明确的执行路径，场景之间互斥
**禁止：** 拆分后的子规则不得互相重叠

### 4. 删除冲突规则
**适用：** N2规则冲突
**要求：** 删除前必须确认删除后不产生N1缺失，必须同步更新所有引用该规则的地方
**禁止：** 不得删除有其他场景仍然需要的规则

### 5. 增加停机条件
**适用：** L2路由层问题，系统不该继续推进时没有停下来
**要求：** 必须定义停机触发条件、停机后的提示格式、用户如何继续
**禁止：** 停机条件不得过于宽泛导致正常流程频繁被打断

### 6. 增加返工条件
**适用：** L2路由层问题，应该返工的节点被跳过
**要求：** 必须定义返工触发条件、返回哪个节点、返工后从哪里重新开始
**禁止：** 返工条件不得导致无限循环

### 7. 增加状态字段
**适用：** L4状态层问题，关键状态没有被记录
**要求：** 必须定义字段名、字段值的枚举、写入时机、读取时机
**禁止：** 不得新增与现有字段重复的状态字段

### 8. 增加守门校验
**适用：** N4规则失效，规则存在但被绕过
**要求：** 在规则执行后增加验证步骤，验证结果不符合预期时阻断流程
**禁止：** 守门校验不得在每个步骤都触发，只在关键节点使用

### 9. 增加输出模板约束
**适用：** L5交付层问题，输出格式不满足下游需求
**要求：** 必须定义输出的完整格式、禁止出现的内容、必须包含的字段
**禁止：** 模板约束不得过于僵硬导致无法处理边缘场景

## 六、优先级判定标准

### P0（阻断级）——满足任一条件
- 问题导致当前流程无法继续推进
- 问题导致最终交付物无法生成
- 问题影响跨节点依赖，导致后续多个节点结果失效
- 问题涉及 Skill D 强依赖字段（目标价格带/认证要求）缺失
- 问题导致 Skill F 判定未通过且无法解决

### P1（严重级）——满足任一条件
- 问题影响单节点输出质量，但不阻断整体流程
- 问题导致 L 置信度条目数量超过单 Skill 7条上限
- 问题导致某个节点需要返工
- 问题导致关键字段被迫标注UNKNOWN
- 问题影响 Skill G 造型意图摘要的完整性

### P2（优化级）——以下情况
- 问题影响有限，不阻断流程，不产生返工
- 属于输出质量提升类优化
- 属于用户体验改善类建议
- 属于边缘场景的覆盖补充

---

## 七、禁止行为清单

- 禁止跳过双轴定位直接给修复建议
- 禁止对同一问题只标注轴1不标注轴2，或反之
- 禁止把多个不同根因合并成一个问题条目
- 禁止用"综合问题"或"整体偏差"替代具体归因
- 禁止在根因未定位前输出修复策略类型
- 禁止把L置信度降级当作问题，L置信度降级是症状不是根因
- 禁止把用户未输入当作系统问题，用户未输入时系统的处理方式才是问题
- 禁止输出"建议优化"替代具体的修复策略类型
