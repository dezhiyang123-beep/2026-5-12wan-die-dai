# boss-review — 老板追问SOP

## 7维度审查模板

对每个维度执行：

```yaml
dimension: "[维度名]"
boss_question: "[具体尖锐的追问——必须引用竞品数据，不得泛泛]"
current_answer: "[当前方案对这个问题的回答，从yaml文件中提取]"
competitor_ref: "[引用g1_intel中具体竞品的数据对比，格式：'[竞品名]做到了[X]，本方案是[Y]']"
weakness: "[当前答案的薄弱点，1句话]"
risk_level: "致命 / 非致命"
```

**7个维度的标准追问方向：**

1. **使用场景**：追问"用户拿出这个产品是什么时候，做什么动作？画面能不能描述得更具体？"
2. **目标人群**：追问"这个人为什么选这个不选[最接近竞品]？他的实际购买理由是什么？"
3. **差异化**：追问"[最接近竞品]已经做了[X]，你的差异是什么？这个差异用户感知得到吗？"
4. **制造可行性**：追问"[最复杂的结构点]，工厂现在有这个能力吗？模具费多少？量产良品率预期是多少？"
5. **成本结构**：追问"BOM$X，目标零售$Y，渠道扣点30%+，毛利率是多少？工厂能接受吗？"
6. **市场规模**：追问"这个需求有多少人有？你说的用户画像，在Amazon搜索量是多少？"
7. **客户买单**：追问"[客户名]的采购上次拒绝了什么类似方案？这个方案避开那个点了吗？"

**追问质量红线：**
- 禁止：包含"是否考虑了"/"是否可以"/"建议"等软性表述
- 禁止：提问不引用具体竞品或具体数字
- 必须：每个维度的boss_question能让设计师立即知道需要准备什么数据来回答

## 假阳性3条必查

### 检查1：决策核真实性
- 问题：概念的decision_core是否真的不可替代？
- 判断：换一个不同的结构/材料/交互方式，还能实现同样的核心价值吗？
- 若能→决策核是包装词，不是真实不可替代点
- 记录：`decision_core_real: 真实 / 虚假`

### 检查2：矛盾消解 vs 折中
- 问题：TRIZ矛盾是真的消解了，还是只是折中（A降一点，B也降一点）？
- 真正消解的标准：改善参数提升的同时，恶化参数没有下降
- 折中的标准：改善参数和恶化参数都有所妥协
- 记录：`contradiction_solved: 真正消解 / 折中妥协`

### 检查3：DFM PASS真实性
- 问题：PASS判定是基于真实制造评估，还是形式过关（没有严格检查就给PASS）？
- 检查点：structure_path中提到的核心结构，有没有对应的制造方式和成本估算？
- 若structure_path描述含有"创新结构"但top10_risks没有对应风险条目→形式PASS
- 记录：`dfm_pass_real: 真实PASS / 形式PASS`

## 致命 vs 非致命判定标准

**致命问题（必须修复才能提交）：**
- 老板7维度中任意一个维度的当前答案为UNKNOWN且无验证计划
- 假阳性检查中任意一条结果为"虚假/折中/形式PASS"且影响提交信心
- BOM超出目标价格带25%且未标注"激进备选"
- 差异化引用的竞品在g1_intel中不存在（数据来源不可追溯）

**非致命问题（建议修但不阻断）：**
- 某维度答案薄弱但不是UNKNOWN
- 细节规格缺失但不影响核心判断
- PPT某页表述可以更强，但内容无误

## 最终判定模板

```yaml
verdict: "通过 / 不通过 / 条件通过"
verdict_reason: "[1-2句话，说明判定依据]"
fatal_issues:
  - issue: "[致命问题描述]"
    dimension: "[关联的7维度]"
    fix_required: "[需要补充什么才能通过]"
non_fatal_issues:
  - "[非致命问题描述]"
```

**条件通过定义：** 有非致命问题但无致命问题，且设计师承诺在提交前补充的。
