# boss-review — 老板追问SOP

## 7维度审查模板

对每个维度执行（full模式）：

```yaml
dimension_review:
  - dimension: "使用场景"
    boss_question: "[具体追问，必须引用竞品数据或具体数字，不得泛泛]"
    current_answer: "[从yaml文件中提取的当前回答]"
    competitor_ref: "[竞品名]做到了[X]，本方案是[Y]"
    weakness: "[当前答案薄弱点，1句话]"
    risk_level: "致命 / 非致命"
```

**7维度标准追问方向：**

1. **使用场景**：`用户拿出这个产品是什么时候，做什么动作？能描述出安装后第一周的使用画面吗？`
2. **目标人群**：`这个人为什么选这个不选[最接近竞品]？实际购买理由是什么，有没有访谈数据？`
3. **差异化**：`[竞品名]已经做了[X]，你的差异是什么？这个差异用户感知得到吗，有没有测试？`
4. **制造可行性**：`[最复杂结构点]，哪个工厂现在有这个能力？模具费估算多少？`
5. **成本结构**：`BOM$X，目标零售$Y，渠道扣点30%+，毛利率是多少？工厂BOM目标价能接受吗？`
6. **市场规模**：`这个需求有多少人有？你说的用户画像，Amazon同品类月销量是多少？`
7. **客户买单**：`[客户名]上次拒绝了什么类似方案？这个方案避开那个点了吗？`

**追问质量红线：**
- 禁止："是否考虑了"/"是否可以"/"建议"等软性表述
- 禁止：提问不引用具体竞品或具体数字
- 必须：每个维度的boss_question能让设计师立即知道需要准备什么数据

## 假阳性3条（full模式必查）

### 检查1：决策核真实性
换一个不同结构/材料/交互方式，还能实现同样核心价值吗？
- 若能→决策核是包装词，非真实不可替代点
- 记录：`decision_core_real: 真实 / 虚假`

### 检查2：矛盾消解 vs 折中
改善参数提升的同时，恶化参数是否没有下降？
- 折中标准：改善和恶化参数都有妥协→折中不是消解
- 记录：`contradiction_solved: 真正消解 / 折中妥协`

### 检查3：DFM PASS真实性
structure_path中的核心结构，有没有对应的制造方式和成本估算？
- structure_path含"创新结构"但risk_top5无对应条目→形式PASS
- 记录：`dfm_pass_real: 真实PASS / 形式PASS`

## 致命 vs 非致命判定

**致命（必须修复才能提交）：**
- 7维度任一当前答案为UNKNOWN且无验证计划
- 假阳性检查任一为"虚假/折中/形式PASS"且影响提交信心
- BOM超出目标价格带25%且未标"激进备选"
- 差异化引用的竞品在竞品矩阵中不存在

**非致命（建议修但不阻断）：**
- 某维度答案薄弱但不是UNKNOWN
- 细节规格缺失但不影响核心判断

## 最终判定模板

```yaml
verdict: "通过 / HOLD / 回流"
verdict_reason: "[1-2句话，说明判定依据]"
backflow_target: "G3 / G4 / G1（回流时必填）"
fatal_issues:
  - issue: "[致命问题描述]"
    dimension: "[关联的7维度]"
    fix_required: "[需要补充什么才能通过]"
non_fatal_issues:
  - "[非致命问题描述]"
```

## 禁止事项

- full模式提问不引用竞品具体数据
- 使用"是否考虑"/"是否可以"等软性表述
- 自己动手修改方案
- 替用户做"要不要继续"的决策
- 没有竞品矩阵时强行对比（输出警告"竞品数据缺失，对比受限"）
