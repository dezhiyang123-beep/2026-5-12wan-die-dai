# Patch Verifier

> 本文件定义验证执行模块：执行 Impact Mapper 的验证计划，判断补丁是否生效且没有引入副作用。
> 由主审计（Claude 本身）执行，不委托给 subagent。

---

## 参考文件与接口

**启动时机：** Impact Mapper 输出验证计划后启动
**输入来源：** `impact-mapper.md` 的验证计划 + `references/regression-cases.md` 中对应用例
**输出目标：**
- PASS / SOFT PASS → 自动进入阶段二静态审计
- FAIL → 退回 `rule-patch-writer.md` 重新生成补丁（最多重试1次）

**最大重试次数：** 1次
若第二次验证仍为 FAIL：
- 停止重试
- 输出人工审查清单，格式：
  ```
  [需人工处理] 补丁 [问题ID] 连续2次验证失败
  失败原因：[具体说明]
  建议人工处理方式：[具体建议]
  ```
- 交给用户决定是否继续

---

## 三层验证（强制执行，不得跳过任何一层）

### 第一层：规则命中验证

检查补丁是否被真正执行：
- 停机条件类补丁：停机是否在触发条件满足时真正触发
- 状态字段类补丁：字段是否在规定时机被写入
- 守门规则类补丁：守门检查是否在节点入口真正拦截
- 输出模板类补丁：格式约束是否生效

**判定：** 规则命中 → 通过；规则未被执行 → 失败，记录具体未命中的规则条款

---

### 第二层：目标问题消失验证

跑对应 A 类用例，确认原问题不再复现：
- 预期结果必须与 `references/regression-cases.md` 中该A类用例的"预期结果"字段**完全一致**
- 不接受"大致符合"或"方向一致"，必须逐项核对

**判定：** 所有预期结果项命中 → 通过；任一项不符 → 失败，记录具体不符的预期结果项

---

### 第三层：副作用验证

跑对应 B 类和 C 类用例：
- B 类用例：确认相邻场景没有被误杀（修复没有拦截不该拦截的正常流程）
- C 类用例：确认健康流程没有被打坏（整体 A→G 流程仍正常推进）

**判定：** 所有用例通过 → 通过；发现轻微副作用但不影响主流程 → SOFT PASS（记录但不阻断）；任一主流程被打坏 → 失败

---

## 判定结果规则

| 判定 | 条件 |
|------|------|
| **PASS** | 三层验证全部通过 |
| **SOFT PASS** | 第一层和第二层通过，第三层发现轻微副作用（需记录但不阻断） |
| **FAIL** | 任一层验证失败 |

**FAIL 时必须：**
1. 输出具体失败位置（哪一层 / 哪个用例ID / 哪个预期结果项不符）
2. 退回 Rule Patch Writer 重新生成补丁
3. 不得输出 PASS 或 SOFT PASS
