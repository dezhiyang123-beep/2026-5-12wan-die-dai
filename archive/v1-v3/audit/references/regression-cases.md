# 回归验证用例池

> 本文件供 Patch Verifier 调用。
> 每次修复后，Patch Verifier 必须从本文件中选取对应用例执行验证。
> 每个补丁至少跑：1个A类用例 + 1个B类用例 + 1个C类用例。

---

## 一、用例结构说明

每个用例包含以下字段：

```
用例ID：[A/B/C类]-[节点]-[序号]
用例名称：[描述性名称]
关联问题ID：[对应的历史问题ID，A类必填，B/C类可选]
关联补丁：[这个用例验证哪类修复]
输入条件：[触发这个用例需要的前置状态]
执行步骤：[具体怎么跑]
预期结果：[正确执行后应该看到什么]
失败信号：[什么情况说明验证未通过]
节点标签：[涉及的Skill节点]
```

### A-A-001：固定安装类品类供电选项跳出验证

**用例名称：** 浴室镜前灯供电方式MCQ反锚点验证
**关联问题ID：** P1-A-001（MCQ-3 Q2供电选项不覆盖固定安装类）
**关联补丁：** Skill A MCQ-3 Q2 品类大类判断分支

**输入条件：**
- 客户：任意
- 品类：浴室镜前灯（固定安装类-住宅湿区）
- 需求：任意

**执行步骤：**
1. PM Simulator 输入上述项目
2. 系统进入 Skill A Step 2 MCQ-3
3. 观察 Q2 供电方式的选项内容

**预期结果：**
- Q2 选项显示固定安装类专用选项：市电硬接(AC 120V) / 低压直流(DC 12/24V) / 市电+电池双供 / 待确认
- PM Simulator 能直接选择"市电硬接AC 120V"
- 供电字段被正确填入状态卡，不再标注[待确认-关键]

**失败信号：**
- Q2 仍显示便携类选项（内置可充电/AA电池/太阳能/混合）
- PM Simulator 被迫跳出选项或供电字段仍为空

**节点标签：** Skill A

### A-A-002：新客户情形B优先级区分验证

**用例名称：** RAB新客户档案字段优先级提示验证
**关联问题ID：** P1-A-002（情形B暂停提示未区分强依赖字段）
**关联补丁：** Skill A 新客户扩展机制情形B分级提示

**输入条件：**
- 客户：任何不在档案中的新客户（如RAB）
- 品类：任意
- 联网取证结果：目标价格带和认证要求均为UNKNOWN

**执行步骤：**
1. PM Simulator 输入新客户项目
2. 系统触发新客户扩展机制
3. 联网取证失败，进入情形B暂停
4. 观察暂停提示的格式和内容

**预期结果：**
- 暂停提示明确区分🔴必须优先补充字段（目标价格带/认证要求）
- 暂停提示明确标注🟡可异步补充字段（品牌风格/主要渠道）
- 提示说明🔴字段是Skill D强依赖

**失败信号：**
- 四个字段平铺列出，没有优先级区分
- 没有说明哪些字段影响Skill D执行

**节点标签：** Skill A

## 五、用例维护规则

### 新增用例规则

每次发现新的P0或P1问题并修复后，必须：
1. 新增对应的A类用例
2. 评估是否需要新增B类用例（防止误杀相邻场景）
3. 如果修复影响核心流程，更新C类健康用例的预期结果

### 用例失效规则

当规则文件更新后，用例的预期结果可能需要同步更新：
- 规则文件版本升级时，检查所有用例的"预期结果"是否仍然有效
- 如果预期结果已过时，更新用例而不是删除用例

### 用例覆盖检查

每次运行 Patch Verifier 前，检查：
- 本次补丁是否有对应的A类用例
- 如果没有，Patch Verifier 必须先新增A类用例再执行验证
- 不允许在没有A类用例的情况下给出PASS判定
