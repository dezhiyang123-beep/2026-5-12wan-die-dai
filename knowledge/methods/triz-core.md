# TRIZ矛盾分析核心

> 调用时机：conceptor在G2生成概念前，从选定方向的behavioral_contradiction提取矛盾。

## 提取流程（4步）

**Step 1：找改善参数**
从选定方向的behavioral_contradiction中提取"要[A]"，A即改善参数。
常用参数：亮度/续航/重量/尺寸/散热/防水/成本/可靠性/易用性/制造难度

**Step 2：找恶化参数**
改善A之后，什么会变差？从同一行为矛盾中提取"就损失[B]"，B即恶化参数。

**Step 3：输出矛盾陈述**
```
矛盾：要提升[改善参数]，但会导致[恶化参数]变差
例：要提升亮度，但会导致续航变差
例：要减小尺寸，但会导致散热变差
例：要提升防水等级，但会导致拆卸维修难度增加
```

**Step 4：给2个解法方向**
```
方向A（材料/结构层）：改变什么材料或结构可以同时改善两个参数
方向B（用户行为/使用模式层）：改变使用方式或场景预设可以绕开这个矛盾
```

## 矛盾模板库（5条常用）

| 改善参数 | 恶化参数 | 解法方向A（结构/材料）| 解法方向B（使用模式）|
|---------|---------|------------------|------------------|
| 亮度 | 续航 | 高效LED+热管散热 | 按场景分级输出（高/中/低档） |
| 便携（尺寸小）| 功能完整性 | 模块化折叠结构 | 单一场景聚焦，减少功能集 |
| 防水等级 | 充电便捷性 | 无线充电+磁吸密封 | 定向使用场景（不需要频繁充电）|
| 握持稳固 | 重量 | 结构减重+橡胶局部覆盖 | 辅助固定机制（磁吸/夹持/挂钩）|
| 成本 | 可靠性/寿命 | 简化机构+提升单零件质量 | 标准化零件降采购成本 |

## 使用规则

- 矛盾必须从behavioral_contradiction字段提取，不能凭空创造
- Mode A（聚焦）：选1个最核心矛盾，出2个解法方向各驱动1个概念
- Mode B（并行）：选2个矛盾，各出1个解法方向各驱动1个概念
- 默认使用Mode A，除非用户指定
